# 99｜运行与 AI 协作指南

本文件是 AI 的统一入口。学生与教师运行同一套课件。先读本文件，再按需要读《环境准备与迁移说明.md》和当前阶段的 Notebook；无需先通读全部工具代码。**实际分析在 `projects/<项目编号>/` 内进行。**公共 Notebook 是复制模板。

若本次只要求“看已有结果/打开网页/学习教程”，按末尾第九节操作；先判断用户是在阅读还是要继续计算。阅读历史材料不需要新建项目或重跑章节。

## 一、每次会话先确定项目、环境和输入

1. 询问或从已有对话确认：这是哪个项目、项目名称、教程练习还是自己的数据。编号用短英文/数字/下划线，中文名称另存。已有明确答案不重复问。不得用默认“当前项目”替所有人做决定。
2. 执行 `./course project list` 查现有项目；首次机器没有环境时先运行 `bash setup.sh`，然后再列项目。询问“继续哪个已有项目，还是创建新项目”，不能覆盖已有目录。
3. 先按《环境准备与迁移说明.md》检查本机。只有 `.runtime/preflight.json` 的本机检查通过才能计算。随包历史结果不能替代检查。
4. 创建或定位项目，然后查看 `project.json`、`results/state.json` 和 `./course --project <编号> status`。状态为等待时，读取记录指向的 `request_*.json`、候选、图表、已确认记录，恢复已有进度；不要反复重新开始。
5. 检查输入文件确实存在，核对物种、组织、测序方式、样本/捕获文库、基因编号和原始计数来源。H5AD 必须明确 `counts_layer` 是 `X`、`raw` 还是某个层；不能仅因数值是整数就断言是原始计数。
6. 自有数据先由 AI 适配**该项目的 Notebook 副本**和材料；保留原分析教学与注释风格。`adaptation.confirmed` 只在实际核对后设为 true，`note` 写清依据和改动。不能把人类骨髓的 MT/HB/免疫 marker 和模型套到植物或其他组织。

### 常用入口（在课程根目录执行）

```bash
bash setup.sh
./course project create practice_01 --name '骨髓单细胞练习' --preset tutorial
./course --project practice_01 status
./course --project practice_01 run 00
./course --project practice_01 run 01
```

自有数据改用 `--preset custom`，把数据、标记清单、模型等放入 `projects/<编号>/inputs/` 后登记相对路径。`tutorial` 仅引用同包示例输入，结果和课件仍是自己的副本。`tutorial_example` 是历史参考，禁止修改或续跑；创建练习项目再运行。

`--project` 放在子命令之前。在项目目录内调用 `../../course` 可以省略它；跨项目操作仍建议显式写出。可在同一安装下并存多个项目；公共环境更新时不能有章节正在运行。

## 二、缺信息时如何与人沟通

使用以下结构，填入刚刚检查或计算得到的实际内容，而非原样复读模板：

> **当前项目/阶段：** ……  
> **我已检查/计算：** 具体文件、实际图表、官网或文献地址及查询日期。  
> **发现与比较：** 缺什么、候选有何区别、人数/指标/图形证据。  
> **我的建议及依据：** 推荐哪条、为什么、还有什么不确定。  
> **需要你决定：** 只问当前继续运行所必需的选择，给出易懂选项。  
> **确认后执行：** 使用哪个候选、保存在哪里、会影响哪些后续章节。

- 若输入资料缺失：先查实际文件名、层与目录，再问用户补充具体材料；不要凭猜测填一个路径。
- 若资源缺失：**检查本地 → 检索可靠来源 → 推荐具体候选 → 获得确认 → 下载/登记/适配**。联网失败单独说明，不能写成“该物种没有模型”。下载需要用户已明确同意；已同意的同一资源无需重复问。
- 对结果选择，能先产生候选结果的就先计算并展示。不能先让学生盲选 QC 方法/分辨率/整合方法。
- 对项目身份、原始计数来源、科学比较问题、外部模型使用等前置条件，先问清后计算。不能为了“先出结果”颠倒顺序。
- 确认必须来自真实用户；记录原文，不把 AI 自己的建议当确认。`--test-only` 只供独立的 `test_only` 验收项目，教学中不得使用。

## 三、逐章运行、等待和继续

`run` 每次只执行一章。正常暂停打印“等待材料/等待确认”，退出成功；发生计算错误才是失败。等待不等于本章完成，不能直接跑依赖它的下一章。

```bash
./course --project practice_01 run 02
# 查看本章 run.json/request_qc.json 指向的真实候选与图表，向用户汇报。
# 用户回复后才填写真实确认原文：
./course --project practice_01 choose 02 qc basic --confirmation '这里填写用户实际回复'
./course --project practice_01 run 02
```

如直接在 Jupyter 按单元格学习，`AwaitingDecision` 是正常停点；登记确认后重启该 Notebook 内核，再按顺序执行。推荐 AI 使用上面的 `course run`，它自动管理内核和同次续跑。

同一输入下再次 `run` 会复用待确认尝试，并核对已确认候选，继续到下一个关键点。改代码、科学配置、原始输入或上游检查点后，旧结果变为 `stale`；按顺序重跑。`run 02 --fresh` 明确新开一次尝试，保留旧结果；旧决定不会自动迁移。

### 关键交互点与必须阅读的证据

| 章节 | 先做与查看 | 必须确认的内容 | 继续方式 |
|---|---|---|---|
| 00–01 导学/导入 | 输入文件、维度、共有基因、样本对应、计数层；异常先查明 | 项目资料与数据适配，不默认借用教程身份 | 登记 `project.json`，逐章运行 |
| 02 QC 候选 | 基础过滤后共同对象；basic/mt/mad 独立对象；分样本/文库保留数量、比例、指标分布、候选交集 | 看结果后选 QC 规则；MAD 在有 mt 时还含 mt 上限，不是与 mt 完全无关的第三类算法 | `choose 02 qc basic`、`mt` 或 `mad` |
| 02 双细胞 | 所选 QC 对象的 Scrublet；按同一次捕获文库运行；分数、预测数/比例、keep/remove 比较 | 保留并标记，还是删除预测双细胞；不能把预测当实验真值 | `choose 02 doublets keep` 或 `remove` |
| 03–04 归一化/降维 | counts/log1p 层、高变基因、PCA/UMAP；确认尺寸及异常 | 常规按原课件推进；异常或需改变参数时说明影响再讨论 | 完成计算并解读，不机械增加确认 |
| 05 批次整合 | 未整合、Harmony、BBKNN 的 UMAP 和坐标；批次混合与真实细胞结构都看 | 选择下游邻居图；混合越强不必然越好。仅有样本编号不能证明技术批次 | `choose 05 integration uncorrected/harmony/bbknn` |
| 06–07 分辨率 | 06 所有分辨率的簇数、样本组成、QC；07 相同 marker 的各分辨率点图/均值/比例 | 粗粒度与细粒度聚类列分别确认，簇编号不当类型名 | `choose 07 coarse_resolution <实际列>`；再 `fine_resolution` |
| 08 手工注释 | 当前逐簇 marker 表、QC 表和 07 的图；填写建议表后汇报理由/反证/不确定 | 接受或修改逐簇建议；证据不足可写 Uncertain，不能硬标一种细胞 | `approve 08 --confirmation '真实回复'` |
| 09 子群 | 先看可选群体及人数，确定研究对象；随后比较两种原有方法 | 先 `target_group`，后确认原图限制聚类或子集重建的解释依据 | `choose 09 target_group <实际名称>`；再 `subcluster_route restricted/recomputed` |
| 10 差异表达 | 先看实际标签/组别/人数，写 `comparison.question/group/reference` | 比较谁、回答什么；不能看到 p 值之后倒选问题 | `choose 10 comparison run` 后 Wilcoxon |
| 11 模型 | 本地/官网材料、适用物种组织和标签；预测后看手工/模型交叉表与分数 | 先确认模型 use；后确认报告使用的真实标签列 | `choose 11 models use`；再 `report_labels <列名>` |
| 12 汇总 | 最终标签、样本组成、有效章节解读及 Word 图片 | 是否需补充解释或调整图；沿用已经确认的主标签 | `run 12` 后复核报告 |

细胞级 Wilcoxon 保留为标记探索教学；它不能替代有独立生物学重复的条件效应检验。模型分数也不等于校准后的正确概率。不同路线均保留其实际文件，选中者形成本章主检查点，后续只读取该检查点。

### 无需或无法运行某分支

05（无整合需要）、09（不做子群）、11（无适配模型）可在用户明确同意后：

```bash
./course --project practice_01 skip 11 --reason '实际搜索范围、缺失情况及跳过理由' --confirmation '用户真实回复'
```

跳过会保存理由并传递有效上游对象；11 跳过时 12 用手工标签继续，不生成假自动标签。其他章节不能用 skip 跨过关键分析。小样本、非 UMI 等导致算法不适用时，应先与用户讨论、适配项目副本，不能只把异常吞掉。

## 四、手工注释：由真实结果生成建议，而非发固定答案

运行 08 后，程序先在**当前尝试的 `tables/`** 导出：

1. `marker_evidence.csv`：每个 `cluster_key + cluster + gene` 一行。列为 `cluster_key, cluster, n_cells, gene, mean_log1p, fraction_expressing, mean_log1p_other, fraction_expressing_other`。后两项对照其他簇；表达比例是 0–1。不能混淆 dotplot 的按基因缩放颜色与这里的原始 log1p 均值。
2. `cluster_qc_evidence.csv`：每个聚类列/簇一行，人数及实际存在的 QC 指标中位数。
3. `annotation_proposal.csv`：每个选定粗/细聚类列的每个实际簇恰好一行；同一聚类列同时用于粗细时只出现一次。

建议表列含义：

| 列 | 谁填、怎么填 |
|---|---|
| `cluster_key, cluster, n_cells` | 程序生成；AI 不得手改簇编号/人数 |
| `level1, level2` | AI 提议标签；粗列至少 level1，细列两级都需完整 |
| `support` | 高/较高/中/低/未定，定性证据支持程度，不是统计概率 |
| `supporting_markers, opposing_markers` | 支持/反对的实际 marker；缺失或未检测清楚区分 |
| `evidence_refs` | 本次证据文件的项目相对路径；多个用分号，可加 `#` 定位。外部文献另在 rationale/报告中给链接 |
| `rationale, uncertainty` | 生物学推理、技术异常和仍需核对之处；不得把教程示例映射当新项目证据 |

AI 应读真实表和图，填表后向用户汇报“拟注释成什么、为什么、哪些簇不确定”。用户修改建议后保存表，再真实确认：

```bash
./course --project practice_01 approve 08 --confirmation '用户实际同意或修订后的确认'
./course --project practice_01 run 08
```

程序会检查完整簇覆盖、人数、标签、证据引用及文件内容。换数据、聚类列、簇成员或上游运行会阻止旧确认；确认后又修改建议表也必须重新确认。`annotation_extra_genes` 可补充需要检查的基因；改变它后重跑 08 导出新证据。公共 `config/` 不存任何固定注释答案。

## 五、模型缺失：先做真实检索，再提出具体建议

官方入口：[模型目录](https://www.celltypist.org/models)、[机器可读清单](https://celltypist.cog.sanger.ac.uk/models/models.json)、[模型元信息](https://celltypist.readthedocs.io/en/latest/celltypist.models.Model.html)。名单会更新，不能把文档里的示例当最新完整目录。

```bash
./course --project practice_01 models search --query 'Immune'
# 只在用户同意确切候选后下载；文件名须来自刚才真实搜索结果：
./course --project practice_01 models download '实际文件名.pkl' --confirmation '用户真实回复'
```

清单检查保存到 `results/resource_checks/model_search.json`，下载进入 `inputs/models/` 并写来源与 SHA256。AI 仍要打开模型说明/论文核对物种、组织、发育/疾病背景、训练平台、基因编号和标签范围；关键词命中不证明适配。不同名称模型可按 coarse/fine 登记，只有一个适配模型就只报告实际存在的那一级。

- **人类/小鼠血液等：** 本地缺失时查当前目录，列出找到的具体候选、来源、匹配点及局限，再问使用并下载哪一个/用户另供/跳过。不能因为“免疫模型”四个字就混用物种。
- **植物或其他物种：** 先核查目录及相应一手资源。若未找到直接适配 CellTypist 的权重，报告检索范围，推荐继续手工注释或请用户提供合适模型。其他框架的模型不能仅改文件名装入 CellTypist。
- **断网：** 写明尚未完成在线核查；列本地真实可用资源并询问提供/恢复网络/跳过。不能虚构搜索结果或下载地址。
- **基因匹配不足：** 先检查基因 ID、同义名和物种；跨物种同源基因转换不是默认操作，需有依据并与用户讨论。

模型确认前展示适用范围；运行后比较实际预测。手工标签和模型标签同时保留，由用户决定报告主标签。自动预测不能反过来充当无条件正确的“标准答案”。

## 六、每章解读、报告更新和重绘

AI 每章完成后读取本次 `run.json/summary.json`、CSV 和**实际图片**，再编写解读。不能只靠文件名、代码或上一次的记忆评价图。解读至少含“目的、方法、结果、解释”，结果写实际数值；解释区分观察/推断/局限，并说明路线选择和未确定群体。

项目报告只需优先打开 `reports/analysis_report.docx`；`analysis_report.md` 是同内容文字导出，`artifact_index.md` 定位全部结果。`sections/` 保存逐章解读源文件，`.meta/` 是程序内部汇编与历史，`notes/` 仅需要学习笔记时创建。

```bash
# 先在项目内写一个解读草稿，图片路径相对于该项目目录。
./course --project practice_01 review 02 --source projects/practice_01/reports/draft_02.md
./course --project practice_01 report
```

建议把草稿放在 `reports/.meta/drafts/`，避免成品目录太乱。示例段落结构见 `assets/report_templates/`。重复 review 替换同一章，不追加重复章节；旧解读保存在 `.meta/history/`。报告绑定当前尝试、正文、引用图片及科学表格的内容。过期解读会从成品撤出并列待更新；不会假装旧结论仍然有效。

### 用户要求“字号小一点/图例不要超界”

1. 判定是排版还是科学改变。字号、边距、图例位置可从本章检查点重绘；过滤规则、基因集合、整合、聚类、注释标签变化应走对应章节的新尝试与下游重跑。
2. 把绘图代码保存到本项目 `notebooks/plot_edits/`（需要时创建），添加中文目的、输入/输出、参数说明。脚本接收 `--checkpoint` 和 `--output`，只读检查点，把新图写入指定输出目录；同名图替换用于报告的原图。核对目标图原来的坐标和配色；Scanpy 后续绘图可能覆盖检查点中的分类配色记录，不能直接取最终配色就宣称与较早的图相同。
3. 执行：

```bash
./course --project practice_01 redraw 11 --script projects/practice_01/notebooks/plot_edits/confidence.py
```

可先复制 `tools/prepare_report_figures.py` 为示例。此示例需要精细模型分数，其他图按实际对象修改。重绘保留脚本和旧图，检查科学数据没有被改动。

4. AI 实际打开新图，检查文字、图例、坐标、裁切和表达是否正确，修订对应解读，再 `review`。这会重新合成 Word，旧图不会继续留在成品里。最终导出还应渲染 Word 检查实际页面；本地无法渲染应如实说明。

## 七、物种和输入资源最小登记

`project.json` 示例字段的解释在 `projects/README.md`。重要原则：

- `capture_library` 指一次捕获实验文库；拆分测序 lane 不应误当独立捕获。QC/Scrublet 需与真实实验设计一致。
- `batch_key` 默认为 samples 仅是教程设置；技术批次与生物差异混杂时不能盲目整合。
- `qc.gene_sets` 可用 prefixes、regex、genes 或 file/column；如植物叶绿体指标使用 `cp`。不支持可靠计算的指标写明确 `disabled_reason`，不能用空集合产生全零后声称质量好。
- `markers` 为 JSON（broad/fine 的类型→基因列表）或 CSV/TSV（cell_type,gene,source，可选 level=broad/fine/both）。必须保留来源与适用性说明，核对数据内是否真有这些基因。
- 本项目 Notebook 是本次分析代码。适配尽量改参数和材料；确需调整代码的地方保留原教学方法，解释改动目的和原因。不为一个新数据集重写整个课程。

## 八、交付或迁移

给学生默认发完整包；标准包只是少了可迁移环境压缩包。两包均含教程输入、模型、历史结果、课件与文档，不含维护记录及自动验收项目。跨机器先重新准备公共环境，再恢复自己的 `projects/<编号>`；不要直接复制已初始化的 `.envs` 或照搬 `.runtime` 就绪凭据。

正式结果解释由实际运行和用户确认产生。教程参考报告与自动验收报告都不能冒充该学生新项目的结论。

## 九、网页展示、海岛教程与 AI 解读配合

### 打开与定位

1. 先明确用户要看哪个项目；已有上下文不重复询问。根目录运行 `bash web/start.sh`，使用输出的本地地址；端口占用时换空闲端口，不终止别人的服务。远程服务器按 `web/README.md` 转发端口。
2. 网页启动只检查展示依赖。不能把“网页已打开”说成分析环境通过；若用户要继续运行，仍执行第一节的环境/输入检查。
3. 网页选择对应项目，在“分析步骤”查看当前尝试、状态、摘要与有效解读，在“结果图册”筛选候选或历史结果。等待用户输入、等待确认、跳过、过期、失败均按原记录解释；不能把候选当最终主线。
4. 页首“原理与读图”进入固定海岛教程，同一主题下有 16 站、图解、插画、术语与资料馆。教程保存独立案例副本，项目切换不会改变它。讲新数据时明确区分教学案例与当前真实结果。

### 每章完成或到达交互点时

- 在当前项目打开本次 `run.json/summary.json`、CSV 和原图。网页提供方便的筛选与放大，也能下载原件；AI 仍须实际看图，不能只读取图形标题或自动提示。
- 对普通完成章节：解释本次观察、依据和限制，按第六节写 `review` 并检查报告。随后刷新网页，核对“本章解读”和 Word 下载已更新。
- 对需要选择的章节：先切换到本次候选路线，向用户展示真实图表和比较，再按第二/三节提问。网页没有确认按钮，不用浏览记录替代用户真实确认；收到答复后才 `choose/approve/skip`。
- 对未知图形/字段：打开生成单元格、实际图例和对应数字表再说明，必要时给出可核对的官方方法依据。缺证据时具体指出缺什么，不从教程强行借一个答案。
- 网页图形说明有两类：SHA256 匹配的历史案例详解，以及根据当前绘图调用提供的阅读提示。后者不是当前研究结论；原图改变后，旧案例详解自动失效。

向用户汇报可使用：

> **项目与尝试：** 实际项目编号 / 章节 / 尝试编号。  
> **请看这些结果：** 网页页签和筛选条件，以及项目内图表相对路径。  
> **图怎么读：** 点/行列代表谁，横纵轴、色条、点大小及表达层。  
> **本次观察与限制：** 引用本次真实数字与图形；区分结果、推断和不确定。  
> **下一步：** 普通章节说明继续内容；需要选择时给建议、依据并等待用户回复。

### 改图后同时更新网页与报告

依第六节在项目内保存绘图脚本，执行 `redraw`，实际检查新图后更新 `review/report`，再点击网页“刷新项目与结果”。核对原图、缩略图、章节解读和 Word 引用一致；过期解读提示不能通过直接改状态文件消掉。

海岛教程不随这次重绘自动更新。用户若明确要求把新案例编成教程，应另建独立素材快照并重新审核，不能覆盖固定教程素材让旧讲解失去对应图。网页新代码和教程更新同样先在临时副本验收，再迁移正式目录。
