## 基因名单很长，怎样找到共同主题

拿到上千个差异候选之后，逐个查名字很费力。我们可以问：某一类功能相关的基因，在这份名单里是否出现得格外多？

比如从全校挑出一组学生，其中会乐器的人占 30%。单看 30% 不知道多不多：如果全校也有 30% 会乐器，就没有明显过度代表；如果全校只有 3%，这份名单就值得进一步关注。

[[ORA]] 的直觉就是**候选比例与背景比例的比较**。这里学生换成基因，会乐器换成属于某个功能集合。

## GO 与 KEGG 像两种功能目录

[[GO]] 分成三大类：BP 描述生物过程，MF 描述分子功能，CC 描述细胞组分。一个基因可以对应多个 GO 术语，术语之间可能存在层级、相似含义与共享成员。

[[KEGG]] 按通路等知识组织基因与反应。它让我们从单个基因走向共同参与的过程，但通路图不是本次实验直接测到的所有反应活动。

本案例使用 `org.At.tair.db` 等匹配拟南芥 ID 的注释资源，由 clusterProfiler 完成 ORA，enrichplot 等工具负责画图。输入 ID 与注释认识的 ID 必须匹配，否则基因可能无法进入有效集合。

## 最关键的不是颜色，而是背景

本例背景先取该比较中有有限检验 P 值的基因，再受到具体数据库注释覆盖限制。**背景不是默认整个基因组，也不能只用显著基因。**

上调、下调和全部差异候选分别可以分析，问题各有不同。all 集合混合方向，不能把它富集出的条目直接称为“激活”。

常用参数包括基因集大小 10–500、BH 多重校正和富集阈值。显著的 GO 条目还能按语义相似性去冗余，本例 cutoff 为 0.75。去冗余是在整理代表条目，并没有重新发现一批独立基因。

## 用真实数字把比例算一遍

ZT4 相对 ZT0 的上调集合中，`GO:0019761`（glucosinolate biosynthetic process，硫代葡萄糖苷生物合成过程）有如下数字：

| 数量 | 本例数值 | 对应什么 |
| --- | --- | --- |
| 功能命中候选 | 26 | 有该 GO 注释的上调候选 |
| 有效候选 | 809 | 可对应本次 GO BP 注释的上调基因 |
| 背景功能成员 | 41 | 有效背景中带该功能注释的基因 |
| 有效背景 | 11,616 | 实际可用于此 GO BP 检验的背景基因 |

候选比例 `26/809 ≈ 3.21%`，背景比例 `41/11616 ≈ 0.35%`，富集倍数约 **9.11**。809 不是全部 1,087 个上调基因，11,616 也不是整个基因组的基因数；注释匹配改变了有效分母。

超几何检验再评估这种过度代表的统计证据，同时检验很多条目时进行多重校正。比例和富集倍数帮助理解效应，校正 P 值帮助理解证据，两者要分开。

## 怎样把富集结果写成合理解释

可以说：“与该过程相关的注释在上调候选中过度代表。”这提供了进一步研究的方向。它尚未直接测量酶活性、物质浓度或代谢通量。

从这个线索走向机制，需要查看命中基因、表达模式、功能背景，并结合其他实验。显著条目数量多，也不能单独说明一个方法更准确。

> 带走一句话：ORA 让候选名单与合适背景比较，功能解释的可信程度取决于分母、注释和证据边界。
