# 富集比例与统计量

## 1. 先定义四个数

过度富集分析中，设 `k` 为候选集合中命中某条目的基因数，`n` 为有效候选基因数，`M` 为有效背景中属于该条目的基因数，`N` 为有效背景基因总数。有效集合受输入、基因 ID 映射和数据库覆盖共同限制，不一定等于输入文件行数，更不应直接写成“整个基因组”。

| 指标 | 计算 | 回答的问题 |
| --- | --- | --- |
| GeneRatio | k/n | 有效候选中多少比例命中该条目？ |
| BgRatio | M/N | 有效背景中多少比例属于该条目？ |
| FoldEnrichment | (k/n)/(M/N) | 候选比例是背景比例的多少倍？ |
| RichFactor | k/M | 该条目在有效背景中的基因，有多少进入候选？ |
| Count | k | 命中多少个候选基因？ |

例如 `k=30,n=200,M=150,N=25000`：GeneRatio=0.15，BgRatio=0.006，FoldEnrichment=25，RichFactor=0.2。它们描述不同方面，不能用同一列名互换。

## 2. 本项目的 ratio 有特定含义

ClusterGVis **0.1.2** 的 `enrichCluster(topn=...)` 在返回展示表时计算：

```r
# 目的：演示 GeneRatio 从比例转成百分数；这是公式示例，不是可从空会话直接完成的分析入口。
# 先从对应结果定义 k（条目命中基因数）和 n（候选分母，必须>0）；没有这两个数会报未定义。100*k/n 的 100仅用于换成百分数，不是背景富集倍数。
# source 加载共用表格/来源函数；file.exists 只在配置存在时读 readRenviron，不会自动为 k/n 赋值。ratio保存计算出的百分数，不写文件。

source("0script/tools/metadata.R")
source("0script/tools/outputs.R")
if (file.exists("0script/project.env")) readRenviron("0script/project.env")
ratio <- 100 * k / n
```

因此该表中的 `ratio` 是 GeneRatio 的百分数，上例为 **15**，不是 FoldEnrichment 的 **25**。这是根据本机指定版本的函数实现核对的，不把一个软件里的列名泛化成所有软件的固定定义。`tRatio` 也不是这里采用的标准字段，遇到时需回到生成代码确认，不能猜成 log2 富集倍数。

原函数的 Top 条目展示表只输出 `group,Description,pvalue,ratio` 等列，未保留完整多重检验信息，且采用 SYMBOL 和数据库默认背景。第 16 章的主结果则保留 TAIR ID，以参与聚类的基因为背景另做检验，并保存 BH 校正值。两表是独立检验，不是同一结果的详表与简表；不能逐行核对，也不能用给前表补列的方式代替后者。

## 3. 比例不是显著性

较大的富集倍数不自动等于更可靠，少量基因可能带来很大的比例；较小 P 值也不等于效应很大。解释时同时看命中数、比例、有效背景、校正值与基因成员。

`pvalue` 为名义检验 P 值，`p.adjust` 为指定方法的多重校正值；`qvalue` 不是 padj 的别名。GO 去冗余只减少相似条目的重复展示，不产生新的实验支持。

GSEA 的 ES/NES 来自完整排序的运行分数及标准化，不等于 ORA 的 FoldEnrichment。两类结果可以帮助提出同一生物学问题，但不能将其数值放在一个轴上当作相同指标。
