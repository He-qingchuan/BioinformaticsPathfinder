# 04 转录组测序数据下载或自备

本章准备真实输入与两张表：`samples.tsv` 说明样本是谁，`contrasts.tsv` 说明谁与谁比较。已有完整数据时不重新下载；本案例已有 21 个文库、42 个双端 FASTQ，保留原文件和来源记录。

## 1. 公共数据：先查记录，再下载

1. 从论文的 Data availability 找到 GEO、BioProject 或 SRA 编号。到 [GEO](https://www.ncbi.nlm.nih.gov/geo/) 阅读样本描述，到 [SRA](https://www.ncbi.nlm.nih.gov/sra) 核对测序类型、文库、双端情况和 run accession。不是同一篇论文的所有样本都必须纳入。
2. 打开 [SRA Explorer](https://sra-explorer.info/)，搜索研究编号，例如本案例 `PRJNA1015621`；按论文与样本记录勾选所需 runs，加入选择列表。
3. 在所选数据的下载区导出 **FASTQ 下载 Bash 脚本**和 **Full Metadata**。保留 `sra_explorer_fastq_download.sh` 与 `sra_explorer_metadata.tsv`；核对脚本里面的链接及保存名，不运行来历不明的脚本。
4. 把两个小文件放到 `0script`，在空的 `2data/rawdata` 中执行下载。SRA Explorer 是查询和导出辅助工具，实际数据来自公共库；它的导出格式见[项目源码](https://github.com/ewels/sra-explorer)。

本案例只选取论文中第 2 天的一个时间窗口，不代表复现整篇论文。样本纳入依据见[研究背景](<附1 研究背景与样本范围.md>)。更换项目时按自己的实验问题选择，不使用固定采样日或标题正则筛选其他研究。

### 执行网站导出的下载脚本

先打开脚本检查。导出的 curl 行通常类似 `curl -L URL -o 文件名`；如需要失败即停和断点续传，可为各行补上 `--fail --retry 3 -C -`，并在脚本开头加入 `set -euo pipefail`。不要对来源不一致的旧文件续传。已有完整数据时跳过此段，避免再次写入同名文件。

```bash
# 目的：运行自己从 SRA Explorer 导出并核实的官方下载脚本；不由本项目重新查询/猜选样本。
# 前提：0script/sra_explorer_fastq_download.sh 已准备，脚本保存名与元数据的文件名列一致。mkdir -p 创建rawdata；
#   cd 进入它，脚本的相对保存路径才落在这里。
# nohup：终端退出时不因挂断信号直接停止；bash：解释下载脚本；../../0script：从 rawdata 返回项目脚本位置。
# > download.log：保存标准输出并更新同名日志；2>&1：错误也并入；&：放到后台，命令立即返回不代表下载完成。最后 cd ../.. 回项目根目录。
# 先确认没有同一下载正在运行；不要重复启动竞争相同目标。完成状态以日志、文件完整性及第 04.5 章检查为准。

mkdir -p 2data/rawdata
cd 2data/rawdata
nohup bash ../../0script/sra_explorer_fastq_download.sh > download.log 2>&1 &
cd ../..
```

下载会持续较久，记录日志位置后按实际耗时检查，不必频繁轮询。退出或进程消失不等于成功；下载完成后看错误日志、预期文件数，再运行第 04.5 章。导出元数据不一定包含 FASTQ 官方摘要；有摘要时另外保存，不能把 `Total bases` 当成压缩字节数。

## 2. 从元数据提取样本表草稿

Full Metadata 可能**每个 FASTQ 一行**，因此同一个 accession 的 R1、R2 出现两行是正常的，不是两个生物学重复。

下面在 R 中将两端配成一行，自动提取 run ID、文件名和来源标题。实现只处理本地表，不查询网站、不下载数据，也不猜实验分组。

```r
# 目的：把双端下载记录配成样本草表，保存为 0script/samples.draft.tsv。
# 运行位置：项目根目录（能看见 0script）；在本章指定环境的 R 中执行。
# 输出：output_file 指定的 TSV；默认 0script/samples.draft.tsv。
#   若该文件已存在，改存 0script/samples.draft.generated.tsv，原文件不覆盖。
#   候选内容相同则复用，不同则报错；group/replicate 必须人工核实后填写。
# 参数设置（下方为本次取值；不需要修改函数内部实现）：
# filename_column：文本列名，必须存在于元数据中，并与下载脚本采用的文件名一致。
#   "FastQ nice filename"：网站整理后的友好名称，本示例和函数默认均用它。
#   "FastQ filename"：公共库原始文件名；若下载脚本采用原名，就选择这一列。
#   自行整理的表也可指定真实文件名列，但不能选标题列代替文件名。
# metadata_file：字符路径；已经从 SRA Explorer 导出的 Full Metadata 表。本函数只读本地表，不查询网站、不下载 FASTQ。
# output_file：以小写 .tsv 结尾的保存路径，相对项目根目录；候选命名按此后缀生成。
#   默认 "0script/samples.draft.tsv"。它不是正式样本表，核实分组和重复后才采用。
# 调用：先加载脚本，再设置参数，最后运行函数。改值后重新执行赋值和调用。

source("0script/scripts/04_sample_inputs.R")
# 经常需要核对：实际下载时使用哪一列文件名。
filename_column <- "FastQ nice filename"
# 通常保持默认：元数据来源和草表保存位置。
metadata_file <- "0script/sra_explorer_metadata.tsv"
output_file <- "0script/samples.draft.tsv"
prepare_sra_samples(
  metadata_file = metadata_file,
  filename_column = filename_column,
  output_file = output_file
)
```

### 查看刚生成的草表

留在上面的 R 会话运行。每行是一个配对 run，而不是一个 FASTQ；查看 `sample_id/read1/read2/source_title`，空的 `group/replicate` 不表示已经核实分组。两个文件若都存在，会分别显示；本次实际保存位置以生成时的信息为准。

```r
# 目的：查看草表及可能的候选表，不写文件，不重新生成样本。
# output_file：沿用上一框设置；sub 只把末尾 .tsv 换成 .generated.tsv。
# file.exists：只看存在的文件；readLines(n = 10)：最多读前 10 行，含表头。
# warn = FALSE：省略末行缺少换行符的提示；cat 的 sep = "\n" 逐行显示。
for (preview_file in unique(c(output_file, sub("\\.tsv$", ".generated.tsv", output_file)))) {
  if (file.exists(preview_file)) {
    cat("\n文件：", preview_file, "\n")
    cat(readLines(preview_file, n = 10, warn = FALSE), sep = "\n")
  } else {
    cat("\n尚无此文件：", preview_file, "\n")
  }
}
```

打开草稿，结合 `source_title` 和论文/实验记录确认 `group`、`replicate`，需要时间分析时再增加时间列。可用电子表格批量填入同组信息，保存为制表符分隔的 `0script/samples.tsv`；已有正式表时先核对，不直接覆盖。

如果来源已提供分组表，可以按 accession 合并实验条件，而不用重新抄写文件名；合并键必须唯一，并检查没有漏行。多个 runs 属于同一个生物样本时，先明确技术重复的整理方式，不能把它们自动当作独立重复。

本案例已核实的正式表直接保留；不要求再从标题生成一次。自己的测序文件不需要 SRA 编号，也不需要运行本节草稿函数。

## 3. 自备材料与表格格式

### FASTQ 入口

将双端压缩文件放到 `2data/rawdata`，在 `project.env` 设置 `DATA_ENTRY=fastq`。大文件可用 rsync、SFTP 等传到该目录；不经过结果网页上传。

```tsv
sample_id	group	replicate	read1	read2
Control_rep1	Control	1	Control_rep1_R1.fastq.gz	Control_rep1_R2.fastq.gz
Control_rep2	Control	2	Control_rep2_R1.fastq.gz	Control_rep2_R2.fastq.gz
Treat_rep1	Treat	1	Treat_rep1_R1.fastq.gz	Treat_rep1_R2.fastq.gz
Treat_rep2	Treat	2	Treat_rep2_R1.fastq.gz	Treat_rep2_R2.fastq.gz
```

`read1/read2` 填实际文件名，不带目录；允许 `.fastq.gz` 或 `.fq.gz`。不必把所有文件改为案例的 ZT 名，只要表中与实际文件一致。每个文件只能归属于一个样本/一个 mate。

### 矩阵入口

设置 `DATA_ENTRY=matrix`，准备 `samples.tsv`，并在配置中填写所用矩阵的真实路径。前 03、05–08 章可跳过。

- 第 10 章需要未归一化基因 counts。
- 第 09、13 章需要 TMM 表达矩阵。
- 第 16、17 章需要 TPM；不做时间分析可不准备。

矩阵第一列为唯一基因 ID，其余列名必须与样本表 `sample_id` 一一对应；列顺序可以不同。数据必须非负、有限且每个样本不是全零。文件名不能代替真实尺度：不能复制一个矩阵并改三个文件名来冒充 counts、TPM、TMM。

### 样本表最低规范

| 列 | 是否需要 | 含义 |
| --- | --- | --- |
| `sample_id` | 必须 | 唯一样本 ID；与矩阵列名对应 |
| `group` | 必须，兼容 `timepoint` | 实际分组；同时提供两列时内容必须一致 |
| `replicate` | 必须 | 组内生物学重复的正整数编号，同组不可重复 |
| `read1`、`read2` | FASTQ 入口 | rawdata 下实际文件名 |
| `time_hour` | 时间分析 | 真实数值小时，同组一致；填写时不能部分缺失 |
| `cycle_use` | 周期分析 | TRUE/FALSE，明确选择纳入周期检验的样本 |
| `gsm`、`srr`、备注等 | 可选 | 来源和附加信息，允许保留，不作为通用必填项 |

样本和组 ID 用字母、数字、点、下划线、短横线，不含路径，避免纯数字和 TRUE/NA 等保留字。基因 ID 按文本读取，可保留 `001` 这样的 ID。CSV/TSV 按列名读入，允许列顺序变化和额外列；不要保存成只有外观类似 TSV 的 Excel 文件。

没有时间设计时，省略 `time_hour/cycle_use` 即可，不需要写案例的时间点。拟南芥案例的时间范围不能直接套用于人、小鼠或其他研究。

## 4. 从样本表生成比较表

实现见 [04_sample_inputs.R](scripts/04_sample_inputs.R)。三个选项分别回答：与基准组相比、与相邻时间相比、两者都保留。相邻比较按真实时间排序，不按组名字符串排序。

| comparison_mode 的取值 | 做什么、适合什么情况 | 必需条件 |
| --- | --- | --- |
| `"baseline"` | 每个非参照组与同一个指定组比较；适合各处理对照同一 Control，也适合各时期对照起始期 | `reference_group` 必须是样本表已有组；不要求时间列 |
| `"adjacent"` | 后一个时间组对紧邻的前一个时间组，观察阶段间变化；不是所有组两两比较 | 样本表有完整、真实的 `time_hour`；此策略不使用 `reference_group` |
| `"baseline_and_adjacent"` | 两类比较都生成，相同方向的重复比较只保留一次 | 同时满足上面两类条件 |

例如 A、B、C 的实际时间为 0、4、8 小时，参照为 A：baseline 生成 B 对 A、C 对 A；adjacent 生成 B 对 A、C 对 B；合并策略生成这三种不同的比较。不是时间实验时不要为了运行 adjacent 人为编造时间。

相邻策略要求每个组对应一个真实小时，而且不同组不能占据同一小时；不满足时停止。如果有处理组和对照组两条时间轨迹，不能直接混成一条相邻序列，应按研究问题在正式比较表中明确指定比较。

函数默认策略是 baseline；下面代码展示的是本项目当前选择，显式传入后以该选择为准。其他任意比较直接填写 `contrasts.tsv`，没有自动 `all_pairs` 选项。

<!-- execute: contrast_table env=rnaseq -->
```r
# 目的：根据正式样本表生成 0script/contrasts.tsv，规定实验组与参照组的比较方向。
# 运行位置：项目根目录（能看见 0script）；在本章指定环境的 R 中执行。
# 输出：0script/contrasts.tsv；若已有正式表，写 0script/contrasts.generated.tsv 候选。
#   这两个输出名由现有函数固定，不是可传入的 output_file 参数。
#   候选相同则复用，不同则停止；候选不会自动替换正式表。
# 参数设置（下方为本次取值；不需要修改函数内部实现）：
# comparison_mode：只能单选 "baseline"、"adjacent"、"baseline_and_adjacent"。
#   三者的比较含义、例子与时间要求见紧邻上表；不能用 c(...) 同时传多个策略。
# reference_group：样本表 timepoint（或其别名 group）列中的一个真实名称，区分大小写；不限定为案例组名。
#   baseline 类策略必须填写，不能留 ""；adjacent 不使用它，可以留 ""。
#   每条比较的正 log2FC 表示 test_group 高于该条 reference_group，并非永远高于同一个组。
# samples_file：正式样本表路径，相对项目根目录；默认 "0script/samples.tsv"。
#   正常项目无需改路径，但要先核实表内样本、分组和所需时间列。
# 调用：先加载脚本，再设置参数，最后运行函数。改值后重新执行赋值和调用。

source("0script/scripts/04_sample_inputs.R")
comparison_mode <- "baseline_and_adjacent"
reference_group <- "ZT0"
# 通常保持默认：正式样本表的位置。
samples_file <- "0script/samples.tsv"
prepare_comparisons(
  comparison_mode = comparison_mode,
  reference_group = reference_group,
  samples_file = samples_file
)
```

### 查看正式比较表与候选表

下面切回项目根目录的 Bash 终端。重点看 `test_group`、`reference_group`、`contrast_id` 和 `enabled`：谁相对谁，哪些比较被启用。候选表用于人工核对，后续默认仍读取正式 `contrasts.tsv`。

```bash
# 目的：分别显示正式表和候选表的前 10 行，不修改或采用候选。
# for：依次查看明确列出的两个路径；test -f：仅在文件存在且为普通文件时查看。
# head -n 10：含表头最多显示 10 行，不进入交互界面，也不读取整张表。
# printf：先显示文件名，避免把两份表的内容混淆。
for preview_file in 0script/contrasts.tsv 0script/contrasts.generated.tsv; do
  if test -f "$preview_file"; then
    printf '\n文件：%s\n' "$preview_file"
    head -n 10 "$preview_file"
  else
    printf '\n尚无此文件：%s\n' "$preview_file"
  fi
done
```

也可以直接编辑比较表，指定任意存在的组：

```tsv
test_group	reference_group
Treat	Control
```

最低需要这两列；`contrast_id`、`enabled`、`comparison_type` 可选，读取时补齐。正 log2FC 表示 test_group 高于 reference_group。一个比较不能两边相同，不能重复同一个方向；是否保留反向比较由实际问题决定，不默认生成所有组合。

最后运行[第 04.5 章准备检查](<04.5 分析前准备检查.md>)。检查通过后再逐章分析；异常样本的判断仍需结合质控、PCA 与实验记录，不能通过填均值或复制样本行补足独立重复。
