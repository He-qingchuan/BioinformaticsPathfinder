0script：分析文档与入口文件

从项目根目录启动终端/R，会话中的相对路径都以项目根目录为起点。以下 Markdown 既说明原理、参数和文件含义，也展示实际代码。代码块按章节顺序执行；只想重画图时先确认该章要求的输入已经存在。

结果阅览与命令行 说明两种分工：终端运行本目录的编号 MD，网页仅展示已有结果，默认本地端口 8766。输入规范 说明最少字段、自动生成比较及换物种时的入口设置；环境依赖与迁移 同步记录。

修改参数和选择运行方式

  • 每章先看代码框顶部的用途和逐项参数说明，再修改下方入口变量或单次调用中的命名实参；无需进入函数内部寻找同一个数字。
  • 函数定义本身不启动分析；单次示例和批量调用任选其一。只重绘用专门代码段，不运行完整批量分析。
  • 连续同名执行标识的代码框在自动运行时共用一个进程；手动运行也放在同一会话。跨任务通过已保存输入和显式 source() 衔接。
  • 改标签、图形样式、Top 富集条目数通常只需重绘；改候选阈值需重新筛选并更新下游；改输入、模型或聚类比例/模块数需重算相应步骤。
  • 差异分析的 FDR/log2FC 阈值和富集的显著性阈值作用于不同集合；本章绘图入口的局部阈值不会自动修改前面已经保存的方向列。
  • 不同参数的试绘成套另存；相同输入和参数可复用完整结果，冲突或缺记录时拒绝覆盖。variant_label 用于保留未进入路径的字号/尺寸变化。旧样式不自动删除。

常见入口：第 12 章 top_n 控制上下调各自的标签数；第 14–15 章 term_num 控制功能条目展示；第 16 章 top_var_props/cluster_numbers 控制聚类组合。主目录结构、样本表和比较表不因此改变。

如何阅读代码和注释

每个代码框先说明目的、前提、输入/输出和参数影响，再列可执行命令；普通说明集中在上方，不逐行夹在赋值中间。相同命令选项在同章首次出现时说明，后面明确引用，避免为每一个文件重复解释。

R 入口按“加载函数 → 设置本次参数 → 具名调用”执行。top_n = top_n 的左边是函数形参，右边是刚设置的变量；明确传入的值优先，只有省略形参时才用函数默认值。改了 MD、配置或脚本后，需重新读取/加载并赋值，再调用；已经打开的 R 会话不会自动更新。Shell 调用使用位置参数，严格按本章顺序传入，不能把 R 的具名写法直接搬过去。

scripts/ 的每个函数前说明用途、全部形参、返回值或写出文件；关键处理段说明筛选、排序和保存依据。嵌套保存函数会使用外层函数已经收到的图幅、目录等值，这些是闭包中的变量，不需要另外去改一份默认值。tools/ 是共用输入、结果保护和执行接口；其中 prepare_inputs.R、sample_columns.R、run_chapter.py 是命令行入口，不当作只定义函数的库来加载。

“参数只影响展示”与“这次调用不重新计算”不同。Top 条目数本身不改变检验定义，但在完整分析入口修改它仍可能执行整步并写入新目录；仅重画已有对象时使用该章明确的重绘入口。GSEA 诊断会按保存对象复算底层统计，不等于只读重绘。并非所有步骤都提供清单保护：部分质控汇总和覆盖率报告会更新同名文件，具体以对应代码框说明为准。

# interface-parameters: ... 和 # dependency: ... 是执行器识别的标记，保留其位置和内容，不当作普通说明删除。CLI 的 JSON 参数限于 catalog.py 白名单，不能把 MD 中所有变量直接塞进 JSON；手动修改 MD 参数入口仍可按原函数接口使用。

源码注释更新会自然改变源文件 SHA256，但不改历史运行记录。当前标准 Rscript 使用不保留源码的函数体，纯注释不改变其语法树/函数体摘要；交互式 R 若启用 keep.source=TRUE，源码位置属性可能使函数体摘要不同。遇到保护提示先核对运行方式和记录，不修改旧清单绕过检查，也不据此宣称统计方法改变。

运行记录

runlogs 的下级文件统一说明如下，不再层层新增 README：

  • execution_history.jsonl：每个执行块一条记录，含时间、环境、代码 SHA256、退出码和日志路径。退出码为 0 只表示该块完成，不能代表所有章节完成。

  • NN_步骤_时间.log/.json：某次执行的详细输出及状态；失败记录保留，不掩盖重试历史。

  • generated：本目录 MD 参数与调用块的执行副本；旧函数导出仅是历史记录。当前函数直接来自 scripts/，不依赖 dump() 生成文件。

  • input_verification：完整文件校验结果；每个 FASTQ 的 MD5 与 ENA 对照。independent_manifest_comparison.tsv 又独立核对已记录的实测大小与 MD5，不仅依赖原记录的 PASS 字样。

  • download_smoke.tsv：小范围下载验证，记录 URL、响应状态、字节数与现有文件片段一致性；不能代替整文件 MD5。

  • 旧资源地址检查及响应头：仅为已取消路线的历史访问记录，不是当前分析入口或待办。

  • environments：四个实际环境的 Conda YAML、平台相关的 explicit 清单、已安装软件 JSON；R 环境另存完整包清单与会话信息。包括固定 GitHub 包版本/提交号，不能仅凭 Conda 清单复原这些 R 包。

  • numerical_acceptance.tsv：独立核对矩阵、过滤/定量片段数、TMM 公式、差异方向、集合交集与热图数值。

  • document_acceptance.json/file_inventory.tsv：某次检查时的链接、PNG 完整性、执行源码状态与实际文件清单；记录时间之后生成的结果需下次更新。

  • source_equivalence_review.json：源码修订的分类复核，明确区分语法等价、参数验证和仍沿用既有结果，不冒充新源码的全量运行。

  • fastp_argument_equivalence.tsv：21 个默认 fastp 命令与真实 JSON 执行记录逐参数一致，另核对带空格文件名的传递，不重复过滤。

  • readability_acceptance.json：所有展示的 R/bash 代码框的功能注释和逐框语法检查，以及与修订前执行代码的语法树/命令记号比较；语法通过不等于分析已运行。

  • parameter_revision_validation.json：本轮改参、重绘、小数据迁移、默认统计回归和独立阅读检查的汇总；详细 QA 输出与真实结果分开保存。

  • exploratory_rescue_acceptance.tsv：只使用模拟矩阵验证均值补救默认关闭、原矩阵不变、非法或重复指定的输入被拒绝；不表示本项目启用了补救。

  • main_ora_acceptance.tsv/diamond_ora_acceptance.tsv：分别核对两套注释的 165 个 ORA 检验集合，检查输入背景、超几何 P 值、BH 校正与去冗余对象的对应关系。

  • *_gsea_acceptance.tsv、*_gsea_table_coverage.tsv：核对完整排序、BH 校正、NES 方向和核心基因，并检查满足大小条件的基因集是否完整出现在返回表中；不等于所有抽样误差都已逐条评估。

  • plot_*_acceptance.tsv：根据比较表和实际显著条目表逐项核对应该生成的图形样式及 PNG/PDF 配对；空结果必须有对应状态记录，不能仅靠图片总数判断完整性。

  • gsea_diagnostics：按注释路线、比较、排序分别保存选定示例的 fgsea 后端表、警告文本与原数值一致性检查；log2err 是抽样误差估计，不是生物学重复的标准差。

  • *_ora_layout_refresh*、*_gsea_figure_refresh*：从现有对象修订图形排版的日志、统计文件前后摘要与执行信息；不重新进行富集检验，没有触及的图形保持原样。

  • time_all_acceptance.tsv、time_*_acceptance.tsv：时间输入的均值/中位数与过滤顺序、高变基因与标签、标准化值、模块富集和 JTK 导出的独立核对；文件名区分完整主线检查与自建注释模块检查。

  • time_layout_refresh*：从已有 Mfuzz 对象修正标签对比度和大模块数图高的日志、前后统计文件摘要、逐图片是否重绘的记录；不重复聚类或富集检验。

  • jtk_period_grid_review.tsv：候选周期记录方式与指定 MetaCycle 实现对齐后，本案例六个对象/表格的前后 MD5 核对；采样间隔改变的小数据测试另在项目外 QA 区，不混入真实结果。

  • historical_large_file_candidates.tsv：历史目录大文件的只读盘点，不是删除清单；同名同大小仍须完整摘要核对，NOT_DELETED 表示盘点时未删除。

  • historical_raw_full_hash_verification.tsv：对上述原始 FASTQ 候选逐个计算完整 MD5，与 ENA 及新项目已通过的校验记录对照；该表记录核验时的状态，实际去重另查下项。

  • historical_raw_duplicate_cleanup.jsonl：验收后仅移除 42 个已核实的重复原始 FASTQ，每个文件均记录删除前计划与完成状态、保留位置和 MD5；恢复时从保留位置复制，不依赖重新下载。其他历史文件不在此次清理范围。

最终验收记录生成后也保存在此目录。程序长时间运行时优先查看日志和输出是否增长，通常按预计完成时间或半小时以上的间隔检查；无需持续刷新。

编号实现与准备检查

scripts/NN_步骤.R 或 .sh 对应同编号 MD 的参数调用；例如 12_volcano.R 包含原有 plot_Volcano 及 run_volcano 入口，14_ora_functions.R 是主线与支线共用的 ORA 函数。函数文件不从运行日志生成，也不要求先运行另一章统计分析。

MD 中的参数变量逐项传入函数；实现脚本头部和关键位置也保留注释。调整 Top 数量、标签、阈值或尺寸时先改 MD 参数，不编辑 generated 下的副本。实际统计方法与既有图形选择不因封装而更换。

04_sample_inputs.R 只整理本地元数据/比较表，不自动查询下载。04_5_check.py 与 04_5_tables.R 负责准备检查。runlogs/04.5_preflight_时间.md/.json 是每次检查报告，04.5_integrity_cache.json 是可复用完整性记录。首次完整检查可能耗时，旧记录信息不足时不能冒充新检查通过。
