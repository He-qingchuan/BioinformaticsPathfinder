04.5 分析前准备检查

本章检查输入是否齐全、格式是否匹配、软件是否可用，不执行分析，不下载、改名或修复文件。报告只说明所选范围的准备状态，不能代替实验设计审核。

1. 运行统一检查

在项目根目录激活 rnaseq 后执行。实现见 04_5_check.py；表格检查复用后续章节相同的读取规则，不另设一套表格格式。

# 目的：统一检查当前入口的常规主线准备情况，不开始分析、不下载或自动修复。先激活 rnaseq，在能看见0script 的项目根目录运行。
# python 后面是检查器路径；无其他参数时读 project.env 的 DATA_ENTRY：fastq 检查 05–15，matrix 检查 09–15。
#   16–20 需另外用 --chapters 指定。
# 关键输出：0script/runlogs/04.5_preflight_时间戳.md 和同名 .json；终端会打印实际路径。
#   04.5_integrity_cache.json 是校验缓存，不是分析结果；新报告不覆盖旧报告。
# 首次完整 gzip 检查会读遍大文件；FASTQ 四行格式/双端 ID 仅抽查前 1000 条。WARN 要阅读，PASS 不证明实验设计和数据尺度正确。
# 可选 --force-full 忽略缓存；--no-software 跳过软件清单检查并标 PARTIAL，但表格/材料校验仍调用 rnaseq的 Rscript，不是无 R 环境模式；
#   --project 指定另一项目根目录；--protein-mapping 仅第 18 章需要时提供人工对应表。

python 0script/scripts/04_5_check.py

不做全部主线，或需要加入时间/非模式支线时，改用下面这种调用，不必先执行默认检查：

# 目的：只检查已经有矩阵时将要运行的样本关系、DESeq2、火山图和热图材料。
# --chapters 9,10,12,13：逗号分隔章节整数，无空格；检查器不运行这些章节，也不要求本次包含的步骤尚未生成的未来结果。
# 其他选项与边界同上一个代码框。需要时间或非模式分析时在这里明确加入 16/17/18/19/20，不能以默认主线PASS 替代支线检查。

python 0script/scripts/04_5_check.py --chapters 9,10,12,13
选项 作用、默认值和允许写法
--project 路径 默认当前目录；填能看见 0script 的项目根目录，不填其中的结果子目录
--chapters 列表 如 5,6,7,8；只能填 5–20 的整数，以逗号分隔，不写 5-8 或 4.5。仅选择检查范围，不控制运行顺序
不加选项 按数据入口检查常规主线；时间和非模式支线未选择，不要求其材料
--chapters 9,10,16,17 例：检查对应主线与时间分析输入；时间点必须是实际实验设计
--chapters 18,19,20 检查非模式支线；需要蛋白、明确映射、数据库及相应主线已有结果
--protein-mapping 路径 第 18 章需要人工核实的蛋白对应表时提供；可由 GTF 明确提取则不填
--force-full 默认不启用；写出该开关才忽略缓存并重新完整读取文件，不在后面加 TRUE/FALSE
--no-software 默认仍检查软件；写出才跳过清单检查并标 PARTIAL，不在后面加布尔值，且仍需 R 做表格检查
--help 打印选项帮助后退出，不检查、不生成报告

不要求所选步骤未来才生成的中间文件提前存在：包含第 06 章时不提前索要 clean FASTQ，包含第 08 章时不提前索要矩阵。单独选第 07 章则需要已有 clean FASTQ，单独选第 08 章需要已有 quant.sf；只选第 09/13/16/17 章时，无论最初从 FASTQ 还是矩阵开始，都检查该章实际要读的矩阵。末端绘图/富集不含第 10 章时需要已有差异表。第 19 章模块分析不含第 16 章时需要已有聚类，具体组合和变体仍在该章执行前逐项核对。此脚本不编排任务，也不代替各章对局部参数和具体结果对象的最终校验。

2. 首次完整检查，以后复用记录

首次核对 gzip 完整性、文件摘要及可用的提供方摘要，会读遍大文件，可能需要较长时间；程序先显示文件数和总大小。FASTQ 另外抽样检查前 1000 条格式和双端 read ID，不将抽样称为全量配对证明。

以后只有文件路径、大小、修改时间、文件身份、摘要预期及检查版本一致时才复用记录。文件发生变化即重检；历史 PASS 若缺少这些信息，不能直接当成当前已验证，也不会修改旧记录假装满足条件。已有案例如果需要首次建立这份新缓存，应预留完整读取所需时间。

有 MD5/SHA256 时，可在 0script/checksums.tsv 记录以下列，md5 与 sha256 至少提供一种：

path	md5	sha256	source
2data/rawdata/Control_rep1_R1.fastq.gz	填写提供方真实32位MD5		提供方清单或官方记录位置

这是格式示意，不能直接拿占位文字执行。path 是当前项目内真实文件位置；source 保存来源记录，不能把自己计算的摘要填成官方提供。可增加 bytes 列记录压缩字节数。本案例已有 download_manifest.tsv 可直接读取，不重新联网获取。Ensembl 的 BSD CHECKSUMS 不应填到 MD5 列，按第 03 章单独核对并保留记录。

没有官方/提供方摘要时报告给出警告：gzip 通过和本地指纹只能说明压缩结构与本地文件身份，不能宣称官方摘要验证通过。

3. 读懂报告

检查报告和缓存保存在现有 0script/runlogs/，不新增结果目录：

  • 04.5_preflight_时间.md：本次逐项状态、问题及处理说明。
  • 同名 .json：结构化结果，便于程序读取。
  • 04.5_integrity_cache.json：可复用的完整性记录，不作为生物学分析结果。

PASS 表示该项通过；WARN 要阅读限制；FAIL 必须处理后再运行；NOT_SELECTED 表示不在本次范围，不是失败。整份报告可能为 PASS_WITH_WARNINGS 或 PARTIAL，不能省略限定词。失败退出码非零，不会自动进入下一章。

查看明确的一份检查报告

# 目的：查看本次报告的前 10 行，不再次扫描大文件。
# report_file：把终端刚打印的完整 .md 路径粘贴在引号内；默认空值仅提示，不读取旧报告。
# test -n 检查非空，test -f 检查存在；head -n 10 先看总状态，细项继续打开该 MD 阅读。
report_file=""
if test -n "$report_file" && test -f "$report_file"; then
  head -n 10 "$report_file"
else
  printf '请将本次输出的 0script/runlogs/04.5_preflight_实际时间戳.md 填入 report_file。\n'
fi

常见处理：缺文件就核对路径和上传情况；样本错配就核对样本表与矩阵列；摘要不符先确认来源，不删除整套数据；参考 ID 不对应则检查组装、release 和映射；OrgDb 不匹配就核实包及 keyType，不通过改字符串伪装已转换 ID。

当前差异模型针对独立重复的组间比较；配对、批次或多因素设计仍需调整模型。时间分析读真实小时，周期范围在第 17 章明确设置，不把案例的 24 小时模板当作所有物种的默认生物学结论。
